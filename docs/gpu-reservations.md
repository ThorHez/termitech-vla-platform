# 按用户预留 GPU

在「机器资源」列表或机器详情的「GPU 资源」中点击「GPU 预留」，勾选具体 GPU 后保存。预留绑定当前登录的个人账号，操作员和管理员可以申请，只读用户可以查看。取消勾选并保存可释放本人的预留，管理员也可以释放其他用户的预留。

- 预留立即生效，持续到用户或管理员主动释放；无需审批。
- 一个用户可在多台机器上预留部分 GPU，一张卡同一时间只能属于一个预留用户。
- 训练自动分配优先选择本人的预留卡，再使用公共空闲卡；其他用户的预留卡不会参与分配。
- 指定 GPU 的训练、推理部署（包括共享显存模式）及部署重启都检查当前执行用户的预留权限。已排队的任务会在实际调度时再次检查。
- 申请不能抢占其他用户的任务、无账号归属的历史任务或外部进程。本人正在执行的平台任务可以补申请预留。
- 释放预留不会停止正在执行的任务，也不会清除实际任务占用。任务完成后，释放的卡才可重新分配。
- 机器离线或卡不再上报时仍可释放预留；新增预留需要机器在线、心跳有效且设备存在。
- 预留控制平台调度；直接通过 SSH 启动的进程不受此权限控制。

资源页分别展示用户预留和实际任务占用。「公共空闲 GPU」及概览的「公共可分配 GPU」不包含用户预留卡，本人预留数单独显示。

机器列表保留「GPU 预留」操作入口。进入机器详情后，在「GPU 资源」区域点击「预留信息」选项卡，可查看全部卡的预留用户、时间和状态；默认「GPU 状态」显示资源监控。「管理预留」可打开申请或释放弹窗。保存后弹窗保留，展示服务端确认的卡号和成功信息。

## API

| 接口 | 用途 | 权限 |
| --- | --- | --- |
| `GET /api/v1/nodes/{node_id}/gpu-reservations` | 查看该机器所有用户的预留 | `platform.read` |
| `PUT /api/v1/nodes/{node_id}/gpu-reservations` | 原子替换本人在该机器上的全部预留 | `training.write`、个人账号 |
| `DELETE /api/v1/nodes/{node_id}/gpu-reservations/{gpu_uuid}` | 释放一张卡的预留 | 本人或具有 `machines.manage` 的管理员 |

PUT 请求示例：`{"gpu_uuids":["GPU-uuid-1","GPU-uuid-2"]}`；传入 `{"gpu_uuids":[]}` 释放本人在该机器上的所有预留，不修改其他人的预留。预留人由登录会话确定，请求不接受代填用户。任何冲突会使整个替换回滚，保留原有预留。

GET / PUT 返回列表，每项包含 `node_id`、`gpu_uuid`、`user_id`、`username`、`display_name`、`created_at`。节点 GPU 数据新增 `user_reservation`，原有 `reserved_by` 继续表示实际任务占用。

数据库初始化会新增 `gpu_reservations` 表，并为训练和推理记录补充可空的 `owner_user_id`。历史记录保持空归属，不自动获得任何个人预留卡的使用权限。API 与调度进程需使用同一版本代码；旧版调度进程不识别用户预留。

## 验证边界

本功能通过本地模拟 GPU、数据库与多用户会话测试，不代表已经在真实 GPU 机器部署或运行训练。
