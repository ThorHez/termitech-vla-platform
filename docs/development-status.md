# 首个可运行版本：开发与验收记录

更新日期：2026-10-15。本文描述当前代码的实际能力；[详细设计](VLA训练平台详细设计V1.0.md) 描述完整目标，两者不等同。

## 已实现

| 模块 | 当前能力 |
| --- | --- |
| 中文控制台 | 工作台、机器与 GPU、资产登记和归档、训练模板、创建向导、任务详情与异常提示 |
| 中央控制面 | FastAPI、持久化模型、节点身份隔离、异步预检、幂等任务提交、数据库调度器 |
| 资源分配 | 单机整组 GPU 原子预约；启动前复核本机 GPU 外部进程；失联或执行状态未知时保留预约 |
| 本地资产 | 数据、初始模型、归一化统计均绑定机器；拒绝跨机器组合；产出关联来源任务和执行代码 |
| Agent 与 Runner | 主动登记和心跳、持久化命令/事件、独立训练进程、重复 START 去重、取消和退出确认 |
| 监控 | 主机 CPU/内存/磁盘、NVML GPU 指标、训练进程树资源、训练指标与日志；采集失败显示未知 |
| 代码追溯 | 每次实际启动保存完整 Git SHA、分支、修改摘要、实际模块路径和本地修改证据；与预检基线比对 |
| 运行恢复 | Agent 重启后重新发现存活 Runner、补传事件；Runner 丢失时进入 UNKNOWN 等待对账 |
| 训练适配 | 可实际运行的 CPU 链路测试；OpenPI SFT wrapper 和本机运行环境接入接口 |
| 部署文件 | 中央服务 Dockerfile/Compose、Agent 配置示例和 systemd 单元、本地一键启动脚本 |

数据和模型保持在原机器硬盘上。平台保存路径和关联元数据，不提供跨机器同步，也不会自动拉取或切换 openpi-umi 代码。

当前平台和 Agent 位于同一仓库、不同目录；openpi-umi 保持独立。训练使用本机 profile 指定的 Python 环境，平台环境不引入 JAX/PyTorch。

## 本轮验证

### 自动化检查

- Python 测试：**50 项通过**，覆盖控制面 23 项、Agent 13 项、适配器 10 项、跨进程集成 4 项。
- 前端：`pnpm build` 通过（TypeScript 类型检查和 Vite 生产构建）。
- 前端格式检查：`pnpm format:check` 通过。
- Python 测试有一条上游 Starlette/httpx 弃用警告，无失败项。

跨进程集成测试使用独立 HTTP 服务、真实 Agent 和 Runner 子进程，验证：

1. CPU 工作负载从预检、排队、启动到完成，产生指标、日志、代码快照和关联产物；重复请求不重复创建任务。
2. 取消实际运行进程，并根据退出确认进入取消终态。
3. 预检后修改代码时，在启动训练进程前拒绝执行。
4. Git 代码未变但运行环境 recipe 改变时，同样拒绝使用过期预检。

其他测试覆盖跨节点资产限制、并发 GPU 预约、身份隔离、失联保留预约、Runner 幂等与重启、PID 复用检查、事件重放、伪造终态日志拦截和产物路径逃逸。

已通过实际网页完成管理员登录、选择本机测试环境、异步预检和任务提交。任务“平台首轮网页验收”完成 30 步 CPU 测试，页面可见：

测试使用 `.local/demo-code` 独立 Git fixture，所有状态位于忽略目录 `.local/`。这是 CPU 合成数据链路验证，不是 VLA 模型训练结果。验收截图保存在本工作区 `.local/ui-code-version.jpg`，不纳入源码。

## 尚未验收或实现

| 项目 | 当前边界及后续工作 |
| --- | --- |
| 真实 SFT | wrapper 已实现；尚未连接真实裸金属、GPU、数据和模型，需为一个明确 recipe 完成小数据训练和 checkpoint 验收 |
| MEM / ReCap / RLT | 页面标为待接入，不能启动；需按对应分支的真实训练协议实现适配与阶段依赖 |
| Docker 训练执行 | 尚未实现；当前训练是 native Python/uv/venv。中央服务的 Docker 部署文件不代表支持容器训练 |
| PostgreSQL / Docker 部署 | 已提供代码与配置，尚未在目标环境运行验证；本轮运行数据库为 SQLite |
| 多用户与项目 | 当前单项目管理员令牌模式；成员、角色、项目隔离、配额和审计检索待实现 |
| checkpoint 恢复 | Agent 重启不等于训练续跑；尚未实现断点恢复、自动重试或机器重启后重新拉起训练 |
| 环境复现 | 目前记录 profile 配置摘要，未完整锁定或散列已安装依赖、忽略文件、驱动和 CUDA 环境；不能据此承诺位级复现 |
| 生产运维 | 需补数据库迁移、备份恢复、日志/事件保留与容量限制、监控告警策略和 HTTPS 部署验收 |
| 长时间预检 | 当前预检在 Agent 命令循环执行，耗时探测可能延迟心跳；生产接入前应拆分预检工作线程并验收超时行为 |

原生 Runner 依赖受信任的 profile 和训练代码，不提供文件系统级隔离。当前支持每台机器独立单阶段作业，不支持跨机分布式训练。

## 下一步验收顺序

1. 接入一台指定裸金属，登记已有代码目录、训练解释器、数据、初始模型和归一化统计。
2. 使用明确的 OpenPI SFT recipe 完成少量 steps 的 GPU 训练；核对显存、loss、真实 checkpoint、取消和 Agent 重启行为，再将该 profile 标为已验收。
3. 实现 MEM `mem_exp` 的训练入口与数据协议，再按真实代码接入 ReCap 和 RLT。
4. 补齐容器执行、多用户授权和生产恢复能力，分别增加对应环境验收。

运行方式和环境配置见 [README](../README.md)，当前接口见 [实现契约](implementation-contract.md)。
