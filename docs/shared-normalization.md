# 多数据集共享归一化参数

新建多数据集训练在确认启动后，训练入口先从本次全部数据集的原始数值样本按混采权重计算一份共享 `norm_stats.json`，然后才初始化训练模型。所有来源使用同一份统计；不会平均各数据集旧文件中的分位数，也不会用最后一个数据集的统计覆盖其余来源。统计扫描只读取所需数值字段。每行只统计一个动作向量，逐帧动作直接取本行，已存储的动作块取第一个时间步。训练时由加载器构造完整的预测窗口。

每行仍保留登记的 DATASET、NORM、数据处理器和混采权重，原有数据集绑定不会被训练改写。多源配置中的旧 NORM 仅保留来源和变更核验信息，样本预检跳过其数值加载，最终训练使用启动时生成的共享统计；即使多行恰好绑定同一个单源 NORM，也不能跳过多源统计。单数据集训练继续使用其所选的统计。

预检冻结数值布局、来源清单、权重、生效 FPS、动作预测长度及统计实现摘要，并在生成的 config 中明确 `auto_shared_norm=True`。预检不会提前遍历全量数据，页面中的状态会显示等待训练启动计算。来源布局或纯数值读取接口不兼容时，预检直接报错。确认提交后，适配器和直接调用的多源训练脚本使用同一个准备函数；自定义平台训练入口也会先完成这一步。

共享统计保存在本次任务独立的 `<exp>-normalization/<fingerprint>/norm_stats.json`，与 Orbax checkpoint 目录并列。相同来源、权重、处理方式和预测长度的本任务结果可校验复用；任何变化都使用新的指纹路径。输入数据及已登记 NORM 不会被覆盖。统计失败时不会进入模型训练。

每个 checkpoint 的 `assets/shared/norm_stats.json` 保存实际用于训练的统计及归一化公式。成功产出的模型登记时，平台同时登记该 checkpoint 内的 NORM 资产，并设置模型的 `norm_asset_id`。模型详情可查看关联；它不会改写数据集的默认 NORM，也不会通过名称猜测模型所用统计。历史模型没有这项产物描述时保持原记录。

## 查看权重、样本数与采样占比

训练数据集卡片和混采权重输入提示同时显示：

- **权重占比**：`wᵢ / Σwⱼ`，仅比较每组填写的重复权重。
- **样本数占比**：`Nᵢ / ΣNⱼ`，比较数据集的原始帧/行数。
- **预计采样占比**：`Nᵢwᵢ / ΣNⱼwⱼ`，按标准多数据集采样估算的来源比例。

例如两组分别有 100、900 个样本，权重为 4、1，三种比例分别为 80%/20%、10%/90%、约 30.77%/69.23%。实际随机批次会波动；自定义采样器、UOT 或分布式入口的实际规则仍以对应实现为准。

样本数优先复用最近一次有效登记校验；缺少时自动读取当前数据集的 `meta/info.json`，也可点击“重新读取样本数”更新。样本数是帧/行数，不是轨迹数，也不乘 `action_horizon`。读取按资产去重、最多两路并发，修改权重直接重算比例，不重新读取数据。

任一组样本数缺失或读取失败时，全组样本数占比和预计采样占比显示暂无法计算，不会把其余已知数据重算成 100%；总样本数为零、权重无效时也会明确提示。这些展示不修改数据、配置或训练采样器。

## 通过训练模板逐数据集计算统计

在“训练模板”选择“计算 norm_stats”（`openpi-norm`），选择在线机器、OpenPI 运行环境和一个或多个已登记的本机 LeRobot 数据集，再为各组数据核对处理方式。统计模板只需要数据和处理配置，不配置已有归一化参数、初始模型权重或混采权重。可调整统计批次大小和数据加载进程数；默认使用 CPU，不申请 GPU。

新建统计配置的数据加载进程数按 Agent 可见逻辑 CPU 数 `C` 推荐：`max(0, min(8, floor(C / 2), C - 1))`，即最多 8 个，且不超过 CPU 数减 1，为主进程留余量；未取得有效 CPU 数时保守使用 0。新配置及没有手动修改记录的统计草稿直接填入推荐值，并随所选机器及 CPU 信息更新；手动修改后保留用户数值，已生成的预检配置保持冻结。统计页面不需要额外点击采用按钮。该数值是起始建议，小数据集也可使用 0；CPU 可见数量不代表空闲核数或资源预留。

默认按本次配置自动生成统计 config：填写动作预测长度和模型动作维度，并为每个数据集选择独立数据处理器或使用与 SFT 相同的自定义字段组合，无需填写代码中的 `config_name`。统计页面不提供模型结构选择；内部兼容配置不加载模型权重、不构建训练模型，恢复旧草稿时保留其既有配置。模型动作维度仍需容纳声明的动作布局；统计发生在模型维度填充前。每组数据独立解析，批量统计不施加训练混采的跨数据集布局限制。独立统计同样每行取一个动作向量。动作预测长度用于核对已存储动作块的形状。

动作预测长度和模型动作维度统一在后面的参数页填写，数据集页不重复展示。状态与动作表示分别沿用当前所选字段的登记标签；统计支持已明确登记的「组合向量（多分量）」，动作以真实完整宽度的单个共享块保留，不猜测内部关节或 EEF 分量。旧草稿的未手改空表示可以补齐，用户已有选择保持；标签缺失或冲突时显示依据并等待确认。

统计页面只配置状态与动作，不展示视觉槽位、图像布局或归一化使用开关。统计配置的视觉项规范化为空；SFT 的相机配置和归一化开关继续保留。预检和完整统计使用同一纯数值读取入口，从 parquet 只投影状态、动作及采样所需的索引列，不读取图像列或解码视频；数据集的视频目录无需存在。源数据与计划核验也只覆盖数值文件和必要元信息，避免为了统计遍历视觉文件。已有代码配方必须提供受信的纯数值统计接口；不支持的处理器会在预检时明确报错，不退回读图方式。

需要沿用项目中的现成配置时，可启用高级代码配方，填写配方名称，并明确沿用其中的数据项或另外选择处理器。自动配置与代码配方只能使用一种；恢复已有代码配方草稿时保留原选择。两种模式都要预检并核对生成的 config 后才能提交。

Agent 先检查每组数据的配方、实际路径、一个处理后的数值样本、统计脚本、缓存和输出空间。预检不会运行完整统计。核对生成的 config 并确认后提交，任务会逐个完整遍历数据集，各自在独立目录生成 `norm_stats.json`。全部成功后，逐份登记名为“数据集名称 norm_stats”的 NORM 资产，并按冻结的数据集 ID 自动绑定到对应源数据集。每个数据集的结果只来自该组原始样本，各组可以使用不同的处理配置和数值维度。

多数据集选择表示“批量独立计算”，不混采数据、不合并旧统计，也不生成一份共享统计。平台适配器分别调用 `compute_norm_stats.py` 的单数据集入口；脚本原有的多源分支仍用于下面的加权共享统计。任务日志、取消和代码追溯沿用现有任务流程；任一组失败时保留已写文件用于诊断，不把未完整通过的批次登记为成功产物，也不提前修改数据集绑定。重新统计成功时可以更新原默认绑定；若计算期间用户已修改绑定，则保留用户选择并在新产物中记录未自动替换的原因。已有训练和传输的冻结资产引用不随默认绑定改变。

机器上的 Agent 需包含批量统计适配器，OpenPI 统计脚本需支持 `--config-file` 和独立的 `--output-dir`。旧版本会在预检时提示升级。恢复旧版单数据集统计记录时仍保留其原始数据选择，不补填已有归一化参数或训练混采权重。

## 从全部原始样本重新统计

共享统计应对本次使用的全部原始数据重新计算。不能平均或拼接旧 `norm_stats.json` 的均值、标准差或分位数，也不能给单源统计换个名字就作为多源统计。

每行混采权重是该源样本的重复倍率。三组数据的权重为 `1:2:2` 时，每个源的统计质量分别为 `N₁×1`、`N₂×2`、`N₃×2`，其中 `Nᵢ` 是完整遍历该源得到的原始样本数；来源数量不同，质量比例也可能不同于 `1:2:2`。正浮点权重直接参与加权经验分布，不四舍五入为整数重复次数。

统计覆盖数据处理器实际拼接、布局和编码下的 `state` 与 `actions`，位于 `Normalize` 之前、模型维度填充之前。归一化掩码、字段顺序、历史长度及动作分块必须与本次训练一致。分位数以 5000 个直方图区间估计，来自全部加权样本，不平均旧文件中的分位数。

## 明确选择训练归一化公式

在“训练方式与参数”中选择本次统一的“训练归一化方式”，适用于单数据集、多数据集、自动组装和高级配方。新建配置默认 q01/q99，可明确改为 Min-Max；已有 Z-score 方式仍可选择。恢复没有 `normalization_method` 字段的旧草稿、模板或重新训练配置时，保持“沿用配方 / 旧配置”，不补写新默认。选择沿用会删除本次覆盖字段。

- Min-Max 使用全部样本的真实最小值和最大值，`lo=min`、`hi=max`。
- q01/q99 使用 1% 与 99% 分位数，`lo=q01`、`hi=q99`。
- 两种方式都计算 `2 * (x - lo) / (hi - lo + 1e-6) - 1`，不额外裁剪。因此分位数方式下，超出 q01/q99 的输入仍可能映射到 `[-1, 1]` 之外。

归一化掩码保持不变，推理反变换使用训练时的同一公式和统计。显式的全局选择会替代组合编辑器的局部归一化选择；原组合中的旧声明保留用于来源记录，不会被静默改写。清除全局选择后才重新沿用配方或原组合的方式。

新生成的共享统计同时保留 min/max 和 q01/q99。仅切换这两个公式不需要重新遍历数据，但必须重新预检、核对新 config 并重新确认，旧确认不能复用。本轮源码升级会改变实现摘要，上一版本已经生成的统计可能需要重算或重新验证；这里不承诺自动迁移旧文件。

新共享统计标记为 `quantile_method="q01_q99"`。选择分位数归一化时，训练与推理都采用：

```text
x_norm = 2 * (x - q01) / (q99 - q01 + 1e-6) - 1
```

即使文件同时记录了 `min/max`，也不会改用它们。归一化掩码中明确跳过的维度仍保留原值；反归一化使用同一公式的逆变换。未标记的旧统计保留既有行为，已有模型不会被静默切换到新标度；新共享产物需要训练和推理环境都使用支持该标记的 OpenPI 版本。

在独立的 OpenPI 训练环境中，使用与本次训练一致的配置执行。如果已有平台导出的本次实际 `training_config.py`，优先直接使用该文件，不需把字段组合、数据路径和权重手抄进静态配方：

```sh
python scripts/compute_norm_stats.py \
  --config-file /path/training_config.py \
  --output-dir /data/shared-normalization/run-001
```

`--config-file` 使用平台导出文件提供的 `build_config(output_dir)` 构建实际配置，然后扫描数据并计算统计；它不会调用训练 `main`，也不会启动训练。此方式必须明确指定独立的 `--output-dir`，并使用与 Agent 启动训练相同的适配器导入路径，确保训练解释器可以导入 `vla_adapters`。首次配置尚未取得平台导出文件时，使用下面的原生配置名称入口；当前页面不会在统计参数尚未通过预检时导出训练配置。

也可使用训练库中已登记并核对过的配置名称：

```sh
python scripts/compute_norm_stats.py \
  --config-name your_multi_dataset_config \
  --output-dir /data/shared-normalization/run-001
```

`--config-name` 与 `--config-file` 只能选择一个。无论采用哪种入口，配置都必须包含本次全部源目录、各自数据处理方式和混采权重。统计脚本完整遍历所有源，在独立输出目录生成同一份包含 `state` 和 `actions` 的 `norm_stats.json`。请使用新的独立目录，不覆盖仍被已有任务使用的统计资产。

CLI 仍可用于提前生成和检查一份共享统计；原生配方使用 `use_merged_norm_stats=True` 与 `shared_norm_stats_path` 可以加载已有的、来源匹配的共享文件。原生多源训练设置 `auto_shared_norm=True` 即可在脚本启动前自动计算，不再需要手工运行 CLI。新的平台多源配置会自动启用该字段。实际执行前需更新机器上的相应训练工程、平台适配器和 Agent；本地实现或测试完成不代表已更新远端运行环境。

## 重新统计与预检

新增、移除、更换或修改数据源、修改混采权重、状态历史、字段拼接顺序、动作布局、编码或归一化掩码后，需要重新预检；自动准备阶段按新的指纹重新统计。仅保持相同原始路径不能证明统计仍然适用。原生配方显式加载已有共享文件时，会核对其来源、权重和处理配置；缺少必要来源证明时拒绝复用。

修改共享 NORM 会更新所有行并清除旧预检。重新预检、核对生成配置并确认后才能提交。历史训练的冻结输入和已有逐组归一化配置不会因当前资产编辑而回写。
