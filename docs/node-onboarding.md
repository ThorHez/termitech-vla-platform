# 由中台远程接入裸金属

机器资源页的“接入机器”由中台执行 SSH 部署。管理员填写远端连接信息与安装路径，测试连接，配置已有训练环境，然后由中台上传安装包、安装并启动 Agent。无需手工下载文件、上传或登录服务器执行安装命令。

## 1. SSH 与安装目录

填写机器名称、裸金属 IP/主机名、SSH 端口（默认 22）、用户名、密码和 Agent 安装目录（默认 `/data2/termitech-vla-agent`）。密码只通过管理员 API 发往当前中台，不保存到浏览器 localStorage/sessionStorage。

Agent 的 systemd 服务使用 SSH 登录用户及其主组运行，训练环境检查、目录访问和训练执行均使用同一账户。例如使用 `root` 接入时，Agent 也使用 `root`；使用普通用户接入时，sudo 只用于安装和管理服务，Agent 仍使用该普通用户。不再自动创建固定的 `vla-agent` 账户。手工 sudo 安装默认使用原 `SUDO_USER`，也可通过 `--service-user` 显式指定已有账户。

点击测试连接后，中台验证密码认证、Linux/systemd、Agent 环境安装条件、Git、root/sudo 安装权限和安装路径。首次连接记录该主机的 SSH 指纹，后续变化会拒绝连接。中台仅使用自己的主机记录，不读取或改写用户的 SSH 密钥和配置。

Agent 环境选择遵循以下顺序，SSH 检查和安装使用同一套发现逻辑：

1. 优先查找已有 Conda，包括 `CONDA_EXE`、`CONDA_PREFIX`、PATH、用户目录、`/opt`、`/usr/local`、`/data` 至 `/data3` 的常见 Miniconda/Anaconda/Miniforge 安装目录，以及用户的 Conda 环境登记文件。不执行 shell 启动文件，也不要求事先 `conda activate`。
2. 发现 Conda 时，使用其 base Python 引导安装，在 `<Agent 安装目录>/.venv` 创建专用 Conda 环境，固定安装 Python 3.11 和 pip。base 只需 Python 3.9+，系统 Python 3.10 不会因此阻止接入。检测阶段只读，不创建或下载环境；页面会显示 Conda、引导解释器的路径和版本，环境创建在安装阶段执行。
3. 没有 Conda 时，按 `python3`、`python` 和版本化 Python 命令查找可用的 Python 3.11+，在同一路径创建独立 venv。版本不足时显示实际路径和版本。

发现的 Conda 不可用或创建环境失败时会报告错误，不回退到系统 Python。Conda 本身的包下载使用该机器已有的 channel 配置，需可访问其软件源；随后 Agent 的 pip 依赖仍使用清华镜像、锁定版本及 SHA-256 校验。专用环境通过绝对路径启动，不依赖交互式激活。已有 Conda 环境更新时复用；已有 Agent venv 在迁移时保留备份，迁移失败恢复原环境。

如果指定安装目录中已有 Agent，探测返回原机器名称、状态目录、输出目录和训练 profiles，向导自动带入，避免重复登记或丢失已有任务记录。已有 systemd 服务使用其他安装目录时，检查会提示冲突；应填写原目录，例如当前 169 使用 `/data2/termitech-vla-platform`。

修改 IP、端口、用户名或安装路径后，必须重新测试连接。已有活动或待对账任务的 Agent 不允许更新。

## 2. 训练环境

| 配置 | 用途 |
| --- | --- |
| 受管本地目录 | 代码、数据、模型和输出可使用的本地根目录，每行一个 |
| 训练输出目录 | 每次 Attempt 的独立输出写入此处 |
| Agent 状态目录 | 节点身份、本地数据库、事件和任务状态；已有 Agent 更新必须保留 |
| 环境名称与标识 | 同机唯一，可登记多个训练环境 |
| 训练 Python 解释器 | 已有训练环境的 `bin/python` 绝对路径，不能只填虚拟环境目录 |
| 训练代码目录 | 该环境实际使用的本机 Git checkout |
| 训练适配器 adapter | 该训练环境支持的训练入口，例如 OpenPI SFT |

Agent 使用安装器创建的独立 Python 环境，训练仍按 profile 的指定解释器运行。平台不向训练环境安装依赖，也不下载模型或同步数据。代码、训练环境、数据和模型需预先在目标机器准备好。

接入阶段不要求训练配方。`recipe` 是一次训练使用的代码配置名称（`config_name`），在“新建训练”中选择或填写。同一环境可以运行多个配方，每次由 Agent 自动预检，无需为每个配方重新安装 Agent。旧环境中的 `recipe` 保留为默认配方。

“新建训练”的配方输入支持联想：选择机器与训练环境后，从该环境代码目录的 OpenPI 配置注册列表读取名称，按关键词包含匹配筛选，不区分大小写，名称开头匹配优先；可点击或用上下键与 Enter 选择。建议标记为“预检时验证”，已有的历史验收记录可单独显示。联想只做有界静态解析，不执行配置代码、不导入训练依赖或占用 GPU；动态生成而无法静态识别的名称会提示不完整，仍可手动输入。切换机器或环境会清空旧建议；离线、超时及旧 Agent 会给出可重试提示。

选中配方后可查看分组详情与 Python 定义，编辑首版支持的数值字段后另存为自定义配方，或为已有自定义配方保存新修订。修订独立保存于中台，不回写训练代码；重新选用时绑定确切版本，由 Agent 对本次版本自动预检。源码版本变化时需更新修订，不能沿用旧的预检结果。操作和执行边界见[配方库说明](recipe-library.md)。

## 3. 远程安装与上线

点击安装后，中台创建持久化部署任务，依次完成 SSH 复验、安装包上传与 SHA-256 校验、私有配置上传、安装/更新独立 Agent 环境和 systemd 服务、启动服务、等待实际 Agent 新心跳及训练环境检查。

网页展示阶段进度、日志和明确失败原因。关闭弹窗不会停止后台任务；可从最近部署继续查看。重复提交同一幂等键不会重复安装，同一目标的并发部署会被拒绝。中台重启将未完成部署标为中断，人工检查后重新提交，不会盲目重跑安装。

安装日志实时区分配置检查、独立 Python 环境、依赖下载与安装、Agent 程序安装、依赖校验、配置写入和系统服务启动。依赖包的下载/安装输出逐行回传；长时间无输出时会记录等待提示与已耗时，不将静默当作失败，也不显示估算百分比。页面显示总耗时、秒级日志时间与当前步骤；自动跟随可关闭，上滚查看历史时暂停跟随。

页面保留最近 300 条，点击“下载完整日志”可导出中台保存的 JSONL。中台完整日志位于 `VLA_REMOTE_STATE_DIR/deployment-logs/<部署ID>.jsonl`，目录权限 0700、文件权限 0600；裸金属上的日志位于 `<Agent安装目录>/logs/install-<时间>-<标识>.jsonl`，具体路径也会记录到部署日志。安装失败后日志保留，临时上传目录清理不影响日志。旧版本历史若没有完整日志文件，只能导出现存阶段日志。

输出在落盘和展示前隐藏 SSH 密码、登记令牌及 URL 凭据等敏感内容。安装日志记录诊断信息，不执行日志中的内容。Agent 启动后的运行日志继续通过 `journalctl -u termitech-vla-agent.service` 查看，两者用途不同。

安装器保留原节点状态，并再次检查活动任务。失败时尽量恢复此前已运行服务，但不是完整事务回滚；若安装阶段失败且服务未恢复，页面会提示检查原因。

“接入成功”需要实际在线节点、对应 onboarding ID、新心跳与指定训练 Python 的环境探测通过，不能仅凭 SSH 命令成功判断。环境检查通过后，创建训练仍会针对所选配方和资产执行自动预检；两种检查均不等于真实 VLA 训练验收。

## 中台地址与 SSH 隧道

普通流程由平台自动决定 Agent 回连方式。长期中台可通过 `VLA_AGENT_CONTROL_PLANE_URL` 设置可达的 HTTPS 基础 URL，Agent 主动直连。没有显式配置时，仅自动采用公开 HTTPS 请求入口，不误用浏览器的本机 HTTP 地址。

当前本机联调脚本提供 loopback 入口，此时中台自动通过已测试的 SSH 连接为目标机器创建反向隧道，在远端 `127.0.0.1` 自动分配端口并写入 Agent 配置。隧道指向中台 `VLA_TUNNEL_TARGET_HOST` / `VLA_TUNNEL_TARGET_PORT`，断线和中台重启后会恢复。无需额外打开终端建立 SSH 隧道。

特殊网络入口仍可在高级设置覆盖。反向隧道仅监听远端 loopback，不开放远端公网监听。

## 凭据与部署依赖

SSH 密码加密保存在数据库中，用于部署与自动重连。加密密钥和专属主机指纹记录位于 `VLA_REMOTE_STATE_DIR`，文件权限限制为当前服务账户读取；API、部署日志和命令行不返回密码或登记令牌。需将此目录与数据库共同持久化备份。

安装包由当前仓库构建：`uv run python scripts/build_agent_bundle.py`。默认 `.local/agent-dist/vla-agent-bundle.tar.gz`，由 `VLA_AGENT_BUNDLE` 指定。Dockerfile 在构建镜像时自动生成。目标机器首次安装需能访问清华 PyPI 镜像 `https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple` 下载锁定依赖，安装日志会显示源地址；这是[清华官方推荐入口](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/)。安装保留 HTTPS、锁定版本、SHA-256 校验及二进制包要求，清除继承的 pip 源与 trusted-host 等覆盖，仅作用于 Agent 独立环境，不写系统或训练环境的 pip 配置。生产 API 运行单个 worker 管理 SSH 后台任务与隧道，独立训练调度器仍按既有方式运行。

## 环境检查边界

Agent 使用训练解释器检查版本、实际 executable、代码目录、Git/OpenPI 模块来源和 JAX 模块可定位性。检查不导入 JAX/Torch，不初始化 GPU。后台定期重新探测，任务启动前仍同步预检。

接入完成后，在资产页原地登记该机器已有 DATASET、MODEL、NORM，在新建训练中选择明确 recipe 并点击“开始预检”。Agent 使用训练解释器自动检查配方、数据协议、归一化统计、模型、实际入口、输出空间与 GPU 配置，返回逐项结果；通过后即可提交训练，无需手工维护验收名单。MEM/ReCap/RLT 仍须逐项完成适配与真实训练验证。

登记资产的“本地绝对路径”支持按前缀联想。例如输入 `/data2/hz`，Agent 列出当前机器受管目录内名称匹配的文件或目录；点击目录可继续下钻，也支持上下键、Enter 选择和 Escape 关闭建议。输入防抖后通过中台请求节点实际文件系统，不读取数据或模型内容，不递归扫描。换机器后清空旧建议；离线、无权限、查询超时或旧 Agent 尚未支持时，会显示原因，仍允许手输路径。联想只辅助填写，不会自动登记资产，也不代替训练预检。

`metadata.validated_recipes`、`metadata.validated_recipe_revisions` 和旧的 `metadata.validated` 可以保留历史记录，但不再拦截新配方。当前每次预检都会生成绑定配方、修订、输入和参数的自动证据；缺少自动证据的旧预检需更新中台与 Agent 后重新发起。自动预检通过不等于已完成梯度更新、checkpoint 保存或模型效果验证。

训练预检、提交及 Agent 启动均使用本次任务的配方，任务详情保存该值。旧任务没有记录时显示“未记录”，不从当前环境推测。使用此功能前需更新 Agent；缺少配方回传的旧 Agent 会明确提示升级，避免预检与实际执行不一致。

## 删除连接与卸载 Agent

机器资源与详情中的管理入口提供两种操作，执行前会显示目标机器和影响范围：

- **删除连接**：从当前可用机器列表移除连接，关闭中台管理的隧道并停用自动重连，清除关联 SSH 凭据；远端 Agent 程序和服务保留。中台拒绝该节点继续上报，重新通过 SSH 接入后方可恢复。
- **卸载 Agent 并删除连接**：通过原已验证的 SSH 连接停止并禁用服务，移除标准 systemd unit，将 Agent 独立环境、配置和身份状态移入受限卸载备份目录。原路径不再保留配置或身份，可重新测试首次创建。训练代码、数据、模型和输出不清除。卸载成功后再删除中台连接和凭据；失败会保留连接并显示原因。

两种操作均拒绝存在活动/排队训练、GPU 预约、待执行命令或其他部署任务的节点。远程卸载还会复查目标机的活动任务和待上报事件，并拒绝危险路径或共享真实训练 Python 环境。不能通过 SSH 管理的历史节点可删除中台连接，但无法从页面直接卸载远端程序。

删除连接与卸载均保留历史训练、资产关联和部署日志。节点分别标记 `DISCONNECTED` / `REMOVED`，默认机器列表和可用资源统计不再包含它。卸载后重新创建会生成新节点身份；历史记录仍指向原节点。主机指纹记录保留，重新创建仍会校验机器身份。
