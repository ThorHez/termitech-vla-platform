# 数据处理组件组合

数据资产的 `dataset_profile.field_annotations` 描述原始状态/动作字段、形状及语义标签。数据如何拼接、映射和归一化由本次训练的数据集绑定决定：`dataset_bindings[].processor.parameters.composition`。同一个数据集可以用于不同训练方案。常规 SFT/ReCap 训练由平台复用 `ComposableDataConfig` 自动组装完整配置；既有 SFT、ReCap、MEM、RLT、UOT 代码配方继续作为高级入口保留。

登记页的采样频率 `fps` 放在数据集特征中，不再单独显示全局动作表示、动作维度、状态维度和动作编码编辑栏；表示在下方按原始字段填写。字段用途为动作时可填写 `horizon`，表示数据中每条样本**已经保存**的动作步数：`[D]` 为 1，`[H,D]` 为 H；状态字段没有此属性。自动读取按原始形状填入，无法确定的高阶形状留空；保存的 horizon 必须与声明及真实元信息一致。该标签不改变模型预测长度；原始单步动作仍可在训练时采样多步未来动作，已打包的动作则继续检查其长度与模型兼容。

## 在控制台使用

1. 登记或编辑数据集资产，自动读取状态和动作字段，确认各字段的 EEF/Joint/夹爪开度、绝对/增量、分量和归属标签。独立夹爪字段可选择「夹爪开度」，分量同步为夹爪；它不会改变机械臂整体的 EEF/Joint 表示，也不证明数值是绝对值还是增量。识别不出的内容保留未知；状态与动作分别描述，不根据维数推测控制语义。
2. 在新建训练的「数据和初始模型」页面选择数据集、归一化资产和混采权重。每个数据集卡片可自动推荐、选择现有处理器，或展开「自定义字段组合」。
3. 在该卡片内依照真实字段配置状态拼接顺序、动作布局、视觉槽位、历史长度及归一化。动作模式、旋转编码、单位、坐标系和任务文本字段可选填；夹爪范围校验默认关闭，需要额外检查时再启用并填写范围。编辑只修改当前训练绑定，资产标签保持原样。旧资产的 `processing` 可手动导入为草稿，不会强制覆盖当前选择。UMI V4 按钮仍只是结构样例。
4. 下一页显示本次处理方案摘要，并按选择的训练方式、模型和机器能力重新校验。需要调整时返回数据集卡片；无需增加一个独立的数据处理步骤。
5. 确认训练方式与参数并预检，检查生成的 Python config 后勾选确认再启动。旧训练环境没有导出支持版本 1 的 `ComposableDataConfig` 时会提示更新训练代码；Agent 也必须支持组合预检和代码预览，不会静默换用旧处理器。

动作布局显示所选动作字段的原始总宽度：`[16,10]` 表示已有 16 步、每步 10 维，分块按这 10 维配置。逐维坐标名称或完整分量标签足够明确时，首次创建草稿会带入分块；也可点击「从数据集填入动作分块」替换当前动作布局。只有 `names=["actions"]` 这类字段级名称时仍能确定总宽度，但不能推断位置、旋转、夹爪各占多少维。更换动作字段或更新源标签不自动覆盖手工布局，界面会实时提示分块总和与原始宽度是否一致。

组合处理会在选择数据集后只读获取当前图像元信息，并按真实字段形状自动填写源布局：例如 `[224,224,3]` 为 HWC，`[3,224,224]` 为 CHW。读取也适用于恢复草稿和套用模板；校准已有布局时显示字段与形状依据。当前页面手工修改布局后会保留该选择，并提前显示与真实形状的冲突；「重新识别图像布局」可再次采用元信息。没有唯一通道轴或读取失败时不默认猜成 CHW，仍可手动确认。历史图像只推断单帧布局，不自动选择时间索引。

此处布局描述源元信息。LeRobot 对 image/video 解码输出 CHW/TCHW，组合工厂会先严格验证解码形状，再恢复到声明布局，之后统一输出模型需要的 HWC。数值图像和深度不套用 RGB 解码转轴；源文件与像素取值校验保持原样。

## 从数据集读取默认值

登记数据集或编辑数据特征时，选择在线机器并填写绝对目录，路径稳定后会自动读取；也可点击「读取数据集字段，推断并填入默认值」重试。读取无需训练环境导入，只由该机器 Agent 读取受管目录内的 LeRobot `meta/info.json`，以及可选的 `meta/tasks.jsonl`，不加载模型或扫描大体积数据文件。

采样率、实际字段清单、动作末轴宽度、统一状态宽度、元信息中明确写出的机器人类型和任务文本可以直接带入。相机字段来自 image/video 声明；状态与动作的字段角色、EEF/Joint、分量和左右归属仅在元信息或坐标名称足够明确时给出候选。`[16,10]` 的动作宽度是 10；仅有 7/10/14/20 维不会证明控制语义。绝对/增量没有确证时保留未知；相对 episode 起点的位姿不等于逐步增量，夹爪也不会继承整个 EEF 向量的增量标签。

界面显示直接读取和推断的来源依据。自动填充只更新未手改的源字段标签，按真实字段名保护手动修改；更换机器或目录后撤回仍未手改的自动值，拒绝晚到的旧响应。读取元信息不会创建或修改处理方案。旧 Agent 返回的字段证据可以安全生成未知语义的标签草稿，不能替代语义确认。归一化策略、视觉槽位和历史长度在本次训练中明确配置；单位、坐标系和夹爪范围无需为了通过校验而补填猜测值。

读取结果是草稿，仍需用原保存按钮确认，读取本身不写入资产或改变运行中的训练。离线机器、旧 Agent、权限不足、元信息超出读取预算时给出明确提示，保留手动填写能力。控制台本地元数据快照不连接真实机器，不能从离线快照读取远程磁盘字段。

## 组件及其边界

| 组件 | 配置内容 | 实际作用 |
| --- | --- | --- |
| 机器人描述 | 型号、单臂/双臂 | 记录真实机器人身份，检查左右臂动作布局；型号不决定自由度 |
| 状态 | EEF/Joint、字段名、每字段宽度、左右/共享、归一化标志、历史长度 | 按声明顺序读取并拼接；状态和动作表示可以不同 |
| 动作 | 原始字段名、EEF/Joint、每臂有序分块、宽度、归一化标志 | 核验动作宽度及模型预测长度；原始动作值保持原编码 |
| 视觉 | 1–3 路 RGB/Depth、CHW/HWC、可选时间索引、标准模型槽位 | 明确映射主视角/左右腕；缺少的槽位填零并屏蔽；深度按明确范围映射为三通道 |
| 编码声明 | 可选 absolute/delta、旋转编码、单位和坐标系 | 留空保留原始数值；填写后核对已有源模式或旋转分块宽度，不执行 IK 或单位、坐标系和旋转转换 |
| 任务文本来源 | 可选真实字段名 | 显式指定时读取该字段的非空文本；留空时优先读 `task`、其次 `prompt`，均无文本时使用空提示，训练不使用语言条件 |
| 夹爪范围校验 | 可选原始最小/最大值 | 启用后检查夹爪数值越界，不缩放；关闭时仍检查所有输入数值有限 |
| 归一化 | quantile/zscore、逐分块归一化标志 | 使用本次绑定的归一化资产，校验原始拼接宽度及所需统计字段 |
| 动作损失 | 真实动作块与补齐维度 | 真实动作维度参与训练，补齐维度屏蔽；逐样本掩码覆盖配方中旧动作维度的全局掩码 |
| 模型变换 | 标准 Pi0/Pi05、Value、Gripper | 复用提示词、图像缩放、分词、动作补齐和状态展平；Pi0 禁止状态溢出截断 |
| 训练阶段辅助字段 | `value_target` / `is_positive` | ReCap Value/ACP 阶段核验真实监督列；阶段及 ACP dropout 仍由训练任务管理 |

这里的 `state_history` 表示样本中**已经存在**的 `[history, width]`，不是自动向前采样历史。动作元信息 `[D]` 使用 LeRobot 的未来时间采样；已打包的 `[H,D]` 直接读取，`H` 必须等于模型预测长度。相机带时间轴时必须显式选择 `time_index`。

含组合方案的混采使用各资产自己的统计，不合并不同布局的原始统计。预检会检查配方的 `data.state_pad_dim`：Pi05 至少容纳展平状态宽度；Pi0 必须等于模型 `action_dim`。Gripper 模型的分类头坐标必须与动作布局的夹爪坐标一致，且这些夹爪块不能归一化，以免分类阈值改变含义。

模型的 `image_keys` / `depth_keys` 必须覆盖资产实际使用的视觉槽位，且 RGB/Depth 分类一致。RGB 默认使用三个标准槽位；使用深度槽时需在配方模型的 `depth_keys` 中明确列出该槽，防止按 RGB 做颜色增强。预检会拒绝声明多路视觉却被模型静默忽略的组合。

首版支持标准 Pi0/Pi05、Value、Gripper 的 LeRobot 输入，最多三个模型视觉槽位。MEM、Hybrid、FAST 以及需要新模型结构或非标准动作变换的场景继续使用原有专用处理器。没有组合配置的旧资产和配方保持原流程；既有 UMI 类和配方不会被批量改写。

机器人型号描述不等于分词器的 `ARM/G/H` 标签。本版组合方案不猜测额外 tokenizer 标签；依赖这些专用标签的旧流程应继续使用原处理器，或在训练项目中明确配置并验证基础 `DataConfig.robot_type`。

## 数据流与追溯

`资产字段标签 + 本次 dataset_binding.processor.composition → 真实字段核验 → 状态/视觉/动作处理 → 绑定统计归一化 → 阶段提示词与模型变换`

预检逐项核验方案引用的原始字段、形状、源标签及相机类型，再验证拼接结果、归一化统计、模型和阶段。未知的 EEF/Joint 表示或矛盾的明确声明会阻止预检；动作绝对/增量声明不影响数值处理，可以留空。当前处理器不执行 EEF/Joint、绝对/增量、单位或坐标系转换。实际工厂必须与本次冻结的 binding 组合完全一致，服务端独立检查组合摘要及实现源码证据。配方覆盖不能改写 `data.composition`。

历史 `dataset_profile.processing` 作为只读旧方案保留，新训练可手动导入或选择其他方案。它不再约束新训练的字段拼接顺序、归一化和视觉槽位，也不会被读取元信息或编辑源标签悄悄修改。源字段的 shape/dtype/names（若已保存）仍必须与真实元信息一致。

预检请求冻结完整资产描述。后续资产编辑只影响新请求，启动使用原请求中的组合配置，并重新核对预检计划与源码/资产证据。SFT 预检主要检查元数据和文件证据，样本数值/夹爪范围等由数据变换读取真实样本时继续检查；这些检查不代表已经完成 GPU 训练或机器人实测。

平台与训练项目分别携带不依赖 JAX 的 v1 配置验证器，使用共享的合法/非法测试样例校验协议一致性。配置只接受有限 JSON 数据，不求值 Python 表达式。

`position_unit`、`joint_unit`、`coordinate_frame`、`action_mode`、`rotation_representation` 和 `prompt_key` 可以省略、传 `null` 或留空，统一保存为空字符串；`gripper_range` 可以省略或传 `null`。填写后仍检查支持的枚举、文本/键名和有限且递增的范围。状态历史长度、实际字段、形状、旋转分块的 3/4/6 维宽度和归一化等输入要求保持；没有声明旋转编码时不根据维数猜测编码名。

自动任务文本只选择未被状态、动作、视觉或阶段辅助输入占用的 `task` / `prompt` 键；候选值如存在但不是标量字符串，会报类型错误，不会把数值转换成任务文本。有效的 LeRobot `task_index` 与任务表映射仍会记录源文件摘要；自动模式没有任务文本时允许空提示，显式指定的任务字段缺失或为空则仍报错。旧版已填写的合法声明及范围继续保留原值；未完成的旧草稿如含空的范围输入，可取消勾选范围校验。此调整不会回写已有 `config.py` 或改动原有专用处理器。

实现入口：平台 `packages/adapters/vla_adapters/composition_spec.py`；训练项目 `third_party/openpi-umi/src/openpi/training/composed_processing.py`；界面 `apps/web/src/ComposedProcessingEditor.tsx`。
