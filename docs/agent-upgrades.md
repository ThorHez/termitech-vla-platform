# 已连接 Agent 升级

管理员在「机器资源 → 管理机器连接」或机器详情的管理入口中选择「升级 Agent」，查看目标机器、安装目录与当前/目标版本后确认。中台复用已保存且绑定此节点的 SSH 连接，将当前中台准备的安装包上传到原安装目录并重启 Agent。无需重新填写 SSH 密码或重新创建机器。

升级只更新 Agent 独立环境和服务。原机器身份、任务状态、训练环境绑定、受管目录、输出与缓存设置保留，训练代码、数据、模型及历史输出保留。配置以目标机器当前落盘内容为准，升级前再次核对，避免把之后修改的设置覆盖成首次接入时的配置。

训练现在由每个任务自己的独立 Runner 负责进程、日志、指标、取消和结束事件。Runner 使用启动时固定的配置快照和版本环境；Agent 负责接收新命令、心跳及转发持久化事件。更新或重启 Agent 不会重启已运行的 Runner，也不会修改它使用的程序或依赖。Agent 暂时离线时，Runner 继续训练和写入本地事件；Agent 恢复后继续上传。

已由独立 Runner 接管且状态明确的运行中训练允许升级 Agent，GPU 预约也可以保留。中台会核对新鲜心跳中每个活动任务的隔离证明，远端会在停止服务前后再次核对 Runner/训练进程身份、配置快照和固定版本环境。旧版任务、状态未知或尚在启动的任务，以及推理部署、资产同步、待执行命令或其他管理任务仍会阻止升级。断开连接和卸载仍要求机器没有活动任务和 GPU 预约。

升级期间暂停接受新训练及环境/存储修改。新 Agent 使用新版本处理后续功能和新任务；已有 Runner 始终保留原版本，直到该次训练结束。通信采用 v1 持久化事件/状态协议，后续修改必须保持兼容，不能通过升级 Agent 改写已有 Runner 的行为。

首次从旧版原地安装环境迁移到隔离版本环境，需要等待当前任务结束后完成一次升级。迁移完成后，新启动的训练才具备运行中升级能力；当前已启动的旧版训练不能直接转换为新 Runner。

升级生成独立部署记录。窗口显示阶段、耗时与日志，支持下载完整 JSONL；关闭窗口后后台继续执行，再次打开管理入口可继续查看最近一次升级。失败或中断时可以重试，重试仍执行升级流程。中台重启会将未完成记录标为中断，不会自动重复安装。

只有节点身份一致、升级后的新心跳携带本次配置标识、实际构建标识匹配目标安装包、训练 Python 环境检查通过，才标记升级成功。SSH 安装命令返回成功不等于升级成功。旧 Agent 未报告构建版本时显示未知，可以通过本功能升级到带构建标识的版本。

## 中台准备安装包

```bash
uv run python scripts/build_agent_bundle.py
```

默认安装包为 `.local/agent-dist/vla-agent-bundle.tar.gz`，可用 `VLA_AGENT_BUNDLE` 指向其他包。构建流程在包内写入版本与确定的构建标识，将相同标识嵌入 wheel；Agent 从自身安装文件读取后随心跳上报。升级会固定本次选定的安装包身份，准备后若包已变化，须重新发起升级。旧包缺少此元数据时需先重新构建。

没有可用 SSH 管理凭据的历史节点无法一键升级，需通过「接入机器」重新验证 SSH。安装包缺失、完整性校验失败或机器忙碌时，页面会显示阻止原因。

安装器在 `<安装目录>/runtimes/<版本目录>` 创建全新环境，安装并检查依赖、程序后，再切换 `.venv` 链接。旧版本目录不会原地更新或自动清理，运行中的 Runner 始终使用原环境的实际路径；旧版 `.venv` 首次迁移时保留为 `.venv.before-release-*`。这些目录会占用额外磁盘空间，当前没有自动回收功能。

失败时会尝试恢复原环境链接、配置及此前运行的服务。失败后应查看部署日志和机器在线状态，排除故障后重试。活动训练期间禁止变更服务账户或迁移旧版环境；systemd 必须使用 `KillMode=process`，以便只停止 Agent 主进程。此功能不升级训练环境依赖，不拉取或切换训练项目代码。

## API

- `GET /api/v1/nodes/{node_id}/management`：查询升级资格、阻止原因、当前/目标版本与最近升级。
- `POST /api/v1/nodes/{node_id}/upgrade`：要求 `Idempotency-Key`，返回 `202` 及部署记录。页面传入 `{ "expected_build_id": "目标构建的64位摘要" }`，防止确认页面展示后安装包改变；兼容无请求体的调用。
- `GET /api/v1/remote-deployments/{job_id}`：读取进度和结果；升级的 `operation` 为 `upgrade`。
- `GET /api/v1/remote-deployments/{job_id}/logs/download`：下载完整日志。
- `POST /api/v1/remote-deployments/{job_id}/retry`：重试失败或中断的升级，使用新的 `Idempotency-Key` 可安全重复提交本次重试。

这些入口遵循 `machines.manage` 权限和现有敏感操作身份确认规则。提交相同幂等键返回同一任务，不会重复安装；其他操作或节点使用相同键会冲突。
