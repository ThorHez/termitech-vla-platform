# 真机部署与本地推理测试

左侧导航的“真机部署”用于把 OpenPI 动作策略启动为部署机器上的推理服务。“机器资源”继续负责机器接入、Agent 和运行环境管理；真机部署直接复用这些机器和环境。

“真机部署”首页只显示部署记录摘要和新建入口，不自动打开第一条记录。点击部署记录进入独立详情，再查看该记录的概览、权重同步、本地测试、服务日志、本地客户端及统一的真机运行与数据回流预览；可通过“返回部署记录”回到列表，详情地址支持刷新和浏览器后退。

每次部署使用一条持久父记录，准备、权重同步、推理服务和测试都是它的子信息。第一次创建同步时即保存父记录，随后启动服务沿用该记录；关闭窗口、取消同步或重新启动服务都不会拆出一条独立的“部署准备”。首页只列父部署记录，取消的同步仅在对应详情的“权重同步”页签内作为历史展示。

父记录通过明确的数据库关联保存运行服务和同步历史；服务采用的权重仍由原有同步凭据准确绑定，不会按训练任务名或机器猜测。尚未启动服务的父记录提供概览、同步、日志与继续配置入口，不表示已经部署成功。旧部署和同步详情地址通过已有 ID 的明确关联解析到父记录，未关联历史不自动合并。历史服务复用同一同步凭据时，保留原有的精确引用，不改变同步凭据的归属。

## 部署流程

1. 在“机器资源”接入测试机器，确认 Agent 在线，并登记 native `openpi-sft` 运行环境。该环境的 Python 必须能导入对应代码目录中的 OpenPI、JAX/PyTorch、`openpi_client` 与 WebSocket 依赖。
2. 进入“真机部署”，选择来源训练任务和已保存的模型产物，核对目标机器、运行环境、推理框架、配置、端口与 GPU。关联训练的模型自动从已确认训练快照生成推理配置；也可填写该机器上已有的 checkpoint 路径，并从目标运行环境的 config 联想结果中选择已有配置。
3. 如果选择另一台部署机器，填写目标保存目录并点击“开始 rsync 同步”。平台在同一事务中保存部署父记录和同步关联，源机器导出已确认的推理配置，再通过已有 SSH 连接传输推理需要的 checkpoint 内容，排除根级 `train_state/` 训练状态目录。同步进度、失败原因、重试和取消操作保存在该部署详情中。文件与配置校验完成后，再点击“部署并启动服务”，服务仍归于同一父记录。同机部署直接使用原目录。
4. 创建部署。目标 Agent 检查目录、权重、归一化参数、文件校验凭据及运行环境，使用所选 Python 启动独立推理进程。权重目录需包含 `params/` 或 `model.safetensors`，并包含 `assets/` 下的归一化参数。
5. 在部署详情查看状态、检查结果和日志。模型加载期间显示“模型加载中”；只有与当前部署身份匹配的 WebSocket 元数据探测成功，才显示“服务就绪”。控制面约每 15 秒安排一次状态探测；机器失联或回执超过 45 秒未更新时显示“状态待确认”，不会持续显示过期的就绪状态。
6. 使用“停止服务”结束该部署拥有的推理及测试进程。停止确认前，部署继续占用资源；机器失联也不会被视为已停止。
7. 已停止的部署可在原记录详情页点击“启动服务”，失败的部署可“重试启动”。启动复用该记录绑定的权重、推理框架、推理配置、机器、端口和 GPU 设置，无需再次同步；平台与 Agent 会重新检查环境、端口和 GPU 资源。每次启动使用独立运行身份，旧的停止命令和延迟回执不会干扰新服务。机器离线、仍有待完成操作或服务状态待确认时不能重复启动；旧 Agent 需先更新。

部署与训练共享 GPU 预约和本机进程锁。存在活动部署时，相关源码回写、环境切换及机器 Agent 断开/卸载会被阻止，避免推理运行中失去其配置与管理通道。

### 真机运行与数据回流界面

进入部署记录的“真机运行与回流”后，在同一张卡内使用 SDK/Eval 准备、运行与采集、人工接管、片段打标与审核、版本发布和训练配置预览。此前的“流程演示”和“数据回流”入口已合并；旧 `tab=mock` 与 `tab=data-return` 地址均映射到统一 `tab=workflow` 视图。

界面使用正式功能文案，不再在页签、按钮、打标面板、日志、回放和版本中重复展示开发阶段标签。工作区顶部保留一处“功能预览”说明：当前尚未连接采集设备，操作结果仅保留在本页，不写入资产或提交训练。文案调整不改变浏览器内的数据与运行实现，也不启用真实设备、训练或服务命令；真实部署状态仍独立保留。

卡片复用一组双相机预览、会话及时间线。新会话的画面中央和采集按钮位置会直接显示下一步操作：启动 SDK、初始化 Eval、开始采集，准备期间显示进度，无需返回卡片顶部。暂停、接管、恢复和结束都对应同一会话，结束后的专家片段可直接审核并生成版本。已结束的轨迹可直接回放与审核。运行遥测、画面断流/恢复和日志也在卡片内查看；画面连接与执行状态分别展示。

一次会话可以连续采集多条 Episode。目标完成时由操作员点击“成功，结束本条”；失败或中止也可分别结束当前条，不自动判断任务完成。结束本条会封存该条帧数、时长与结果，并保持当前 SDK/Eval 准备和会话身份，进入“待下一条 Episode”；整理场景期间不录制、不自动复位或启动下一条。用户手动点击“开始 Episode 002”后，新条从零计时、从零帧开始，继续归属同一次会话。“结束整个会话”终止本次全部采集，尚未单独确认结果的当前条记为未判定，已结束条的结果不变。

“本会话 Episodes”记录每条的状态、结果、时长和帧数，支持回放。当前条仍在采集时查看旧条，会明确显示两者状态，并提供“查看当前采集”返回；封存条可直接打标与审核。Episode 结果也随来源片段写入版本快照，不会让策略上下文自动获得专家数据资格。

在回放中点击“片段打标”，或从“打标与审核”的片段进入，可在同一组画面旁设置帧区间，标记成功/失败、问题类型、纠正意图和说明。一个片段支持多条区间标签及编辑、删除；标签区间不能越过源控制片段，录制中的片段结束后才可打标。语义标签在独立时间线上展示，审核页可筛选已打标/未打标。打标不会改变原始控制来源、专家有效性或保留/排除状态，也不会自动裁剪回流片段。策略或无效上下文可打标供分析，仍不进入专家数据。

发布时同时封存片段标签。后续改标不会改写旧版本；保留片段的标签修订后再次发布生成新版本，相同片段与标签内容则复用已有版本。版本详情可查看发布时的打标快照。当前版本与配置仍为本页预览数据，离开页签后重置。

### JAX 与 PyTorch 推理框架

新建部署的“启动推理服务”阶段提供“自动识别 / JAX / PyTorch”。框架与 GPU 使用方式分别保存，不根据 Thor、RTX 4090 等设备名称强制决定。`params/` 是 JAX checkpoint，根目录 `model.safetensors` 是 PyTorch checkpoint；两者仍需匹配同一模型结构、推理处理配置和 `assets/` 归一化参数。显式选择框架时，Agent 会核对实际权重格式；选择 PyTorch 不会把 JAX 权重转换成 PyTorch，选择 JAX 也不会反向转换。

两种格式同时存在时，自动识别会要求明确选择。当前 OpenPI 加载器只要发现 `model.safetensors` 就进入 PyTorch 路径，因此要运行 JAX，需使用不含该文件的独立 JAX checkpoint 目录。当前内置 PyTorch 路径只接受模型动作维度为 32 的 Pi0/Pi05 配置，不把 FAST、价值模型或自定义记忆模型隐式替换为 PyTorch 动作策略。

部署记录同时保存所选的 `inference_backend`（`auto`、`jax` 或 `pytorch`）和 Agent 确认的 `resolved_backend`（`jax` 或 `pytorch`）。详情区分所选框架与实际识别结果；未取得回执时显示等待识别。重新启动沿用已保存的选择，并重新验证权重与环境。

指定 JAX 或 PyTorch 要求目标 Agent 心跳声明 `POLICY_DEPLOY_BACKEND_V1`；旧 Agent 可继续按自动识别方式部署，但不能把忽略显式选择的回执作为框架确认。此能力检查只限制推理启动，不影响已有的模型导入或权重同步。

计划在 Thor 上使用 PyTorch 时，需先准备与推理配置一致的 PyTorch 权重，以及目标机器上能够运行对应模型的 Python、PyTorch/CUDA 和 OpenPI 环境。当前改动建立框架选择、校验与运行回执，不包含权重转换、Thor 专用依赖安装或加速后端。跨机器推理配置现有的源码、适配器、依赖版本及 tokenizer 校验继续执行；平台不会为了跨架构部署跳过这些检查。本次未进行 Thor 硬件模型加载、延迟或精度验证。

### 推理 GPU 模式

创建推理部署时可选择“独占 GPU”或“与图形桌面共享”。训练继续使用独占判定；推理选择共享模式不会改变训练调度规则。

- 独占模式要求没有 GPU 进程、利用率不超过 5%，且已用显存不超过总量的 2% 或 128 MiB（取较大值）。
- 共享模式允许 NVML 明确识别的纯图形进程，例如桌面、浏览器及远程桌面。计算进程、同时属于计算和图形的进程、无法确认类型的进程仍会阻止启动。共享模式不以桌面产生的 GPU 利用率或少量已用显存直接判断忙碌。
- 共享模式需填写预计推理显存预算，默认展示 16 GiB，可按实际模型调整。剩余显存必须至少覆盖预算和额外 1 GiB 余量；使用 NVML 报告的实际可用显存，不将“总量减已用”当作可分配显存。预算是启动准入估计，不是硬件隔离或峰值显存保证。模型加载和推理时仍可能因实际峰值超过可用容量而失败。
- 两种模式均保留平台训练/部署预约互斥及本机 GPU 锁。共享模式只与图形进程共享，不允许平台在同一张卡叠加多个训练或部署。Agent 启动时重新读取 NVML，推理进程拿到本机 GPU 锁后、加载模型前再次复核，避免使用已经过期的网页快照。

共享模式要求 Agent 心跳声明 `POLICY_DEPLOY_SHARED_GPU_V1` 并提供真实空闲显存与进程类型。旧 Agent 或未知状态不能作为共享依据。部署请求、Agent 配置记录和服务健康回执绑定所选模式与预算，不能把忽略了共享参数的旧服务报告为就绪。JAX 推理进程关闭预分配。

### 模型导入与推理启动分别检查

远程导入、rsync 同步及推理配置导出不要求选择 GPU，也不要求目标 GPU 空闲。配置导出进程使用 CPU；复制阶段检查机器连接、文件、目录权限、磁盘空间和配置合同。同步完成后的“部署并启动服务”才执行所选模式的 GPU 准入检查。没有 GPU或 GPU 正忙时，仍可完成模型导入并稍后启动推理。

### 推理配置来源

关联训练任务时，无需填写推理配置名称。页面展示来源训练、冻结配方、已确认配置摘要和模型参数，控制面从该快照确定名称；同机 Agent 恢复已确认的训练配置，导出推理所需模型和观测/动作处理合同，保存为部署目录中的 `inference-config.json`，实际服务使用相同的模型与处理配置。标准配置使用安全 JSON 恢复；依赖自定义构造器的同机配置保留经过校验的冻结解析过程，在文件中明确标记 `portable: false` 并记录实际模型和处理合同。训练专用监督字段不进入推理输入。缺失确认、摘要不匹配或不支持的处理合同会明确阻止部署，不会替换成基础配方。跨机部署使用权重同步时绑定的推理配置和来源训练快照，不依赖目标代码中存在同名自动配方。

手动选择已有 checkpoint 时，“推理配置名称”支持联想目标机器、所选运行环境代码中实际存在的 OpenPI config。仅登记过的名称不能作为该配置存在的依据；必须选中或精确匹配已发现的配置。切换机器或运行环境会清除原选择并重新查询。训练页面原有配方选择行为保持不变。

自动生成配置和已有配置发现都不加载模型或占用 GPU；服务启动后的模型加载与健康检查仍独立执行。

## 跨机器 rsync 同步

源机器和目标机器均需在线，并在“机器资源”具有已绑定主机指纹的 SSH 接入记录。两端安装 `rsync` 与 Python 3。连接由平台保存的加密凭据建立，不把密码交给浏览器或 Agent；两台机器无需互相直连。管理服务通过两条 SSH 连接转发 rsync 协议流，不将大权重缓存到管理机硬盘。

平台同步推理需要的 checkpoint 内容，包含参数文件、Orbax 元数据、`assets` 中的归一化统计，以及独立的 `termitech-policy.json` 推理配置。checkpoint 根级的 `train_state/` 目录及其子树不参与扫描、哈希、传输或完整性比对；源目录保持原样，既有部分文件保留。普通同名文件和其他路径中的同名目录不被误排除，符号链接仍按原规则检查。文件数、总大小和进度按筛选后的内容计算。训练数据和初始模型不随之复制。源端通过已确认的配置恢复模型结构及数据变换，导出有明确构造器白名单和大小限制的 JSON；目标端校验项目源码相对文件哈希、推理适配器版本、关键依赖版本和 tokenizer 词表。原训练机器上的绝对数据路径无需在目标端存在。尚不能安全序列化的配置会明确失败，不会静默替换为基础配方。

每个同步任务使用独立的部分文件目录，成功后发布到“目标保存目录/同步任务 ID”。平台不使用 `--delete`，不覆盖其他模型或目录。开始时检查源文件、受管路径和目标空间；完成后按同一排除规则重新核对源清单、逐文件 SHA-256 与目标清单，全部一致才标记成功。拒绝符号链接、特殊文件、路径逃逸和与源 checkpoint 冲突的配置侧车文件。

点击“开始 rsync 同步”后，按钮旁先显示创建状态；收到任务回执后立即显示进度卡，再持续刷新传输状态。创建失败的原因直接显示在同步按钮附近。`POLICY_DEPLOY_CHECKPOINT_SOURCE_MISMATCH` 仅作为黄色警告：所填 checkpoint 未登记为所选训练的产物时，仍可继续同步和部署，并继续使用所选训练的已确认配置。警告随同步任务和部署记录保留，不需要额外确认；不会把该目录重新登记为该训练的产物。目录访问权限、文件完整性、推理配置摘要和模型加载检查继续执行。

同步创建和重试前先检查两端保存的 SSH 凭据能否解密，失败时明确指出源机器或目标机器，避免等待配置导出后才报错。准备推理配置时可能首次下载 tokenizer 等小型依赖；此阶段尚未传输模型文件，页面显示阶段说明和不定进度，总大小与文件数标为待统计。实际传输并获取总量后才显示字节百分比。最近日志、任务耗时与最近状态回执分别展示；状态回执刷新不代表已有新的文件传输进展。

失败、取消或服务重启中断后，部分文件保留。同一同步记录可重试并复用已传输文件；如果源权重、配置或机器绑定已变化，则要求重新创建同步任务，避免把不同模型拼到一起。用户可在关闭创建窗口后继续查看记录。取消同步不会删除原模型或已发布的模型目录。

取消后，部署父记录继续保留，取消的同步在该记录的“权重同步”页签中默认收起，保留日志和重试入口。新建部署窗口中的已取消同步详情也默认收起。详情中显示的百分比标为“停止时进度”，用于记录取消前已完成的部分；取消后的卡片不表示仍在传输。

“同步校验完成”证明文件与配置已完整到达，不代表目标运行环境已通过模型加载。只有用户随后确认部署、目标 Agent 验证环境并完成 WebSocket 健康检查，才显示服务就绪。

## 本地单次推理测试

把一帧观测存为部署机器允许访问目录内的 JSON 对象，字段、相机名称、图像布局和状态维度应与推理数据处理器一致。图像可写为嵌套数组。

普通数组会通过 `numpy.asarray` 保留其数值类型。对于标准代码配方，需根据其推理合同明确指定图像类型；可把数组写为 `{"__array__": [[[0, 0, 0]]], "dtype": "uint8"}`。测试工具支持 `uint8`、`uint16`、`float32`、`float64`、`int32`、`int64` 和 `bool`，不会仅凭字段名称猜测 RGB 或深度类型。

组合处理配置接受登记的原始观测字段，按明确的字段宽度与历史长度拼接状态，按相机的 CHW/HWC、RGB/深度种类及深度范围处理图像。RGB 支持 0..255 整数或 0..1 浮点数；深度值保留数值精度后再按训练范围映射。输入无需未来动作、价值目标或其他训练监督标签。输出动作按声明的 `action_layout` 去掉训练填充维度，保留相同归一化和模型输出变换。ACP 默认预测正条件动作，可用单个 0/1 的 `is_positive` 明确切换推理条件；推理时不随机丢弃该条件。

在部署详情填写该 JSON 的绝对路径并执行单次测试。Agent 读取一份固定快照后异步调用推理服务，返回动作张量形状、耗时、有限值检查和本机输出文件路径。测试最长运行 120 秒。输入错误、推理异常或超时会记录为测试失败，部署日志保留详细原因。

此测试只计算动作，不把动作发送给机械臂。服务就绪证明模型完成加载并可提供元数据；单次测试通过证明该观测可以完成推理。两者都不能证明机械臂轨迹、安全边界、抓取成功率或实际硬件执行。真机动作执行仍须由本地机器人客户端按照其控制协议和既有运动限制完成。

## 连接本地客户端

服务默认仅监听部署机器的 `127.0.0.1`，例如 `ws://127.0.0.1:8000`。在部署机器上运行的机器人客户端可直接使用该地址。这里的 `127.0.0.1` 指部署机器，不是打开管理网页的电脑。

如果客户端运行在另一台电脑，可通过已有 SSH 连接转发端口：

```sh
ssh -N -L 8000:127.0.0.1:8000 user@deployment-host
```

保持 SSH 连接，在客户端电脑连接 `ws://127.0.0.1:8000`。如本机端口已占用，可将 `-L` 左侧端口改为其他空闲端口。部署页面提供可复制的 Python 客户端示例。

## 配置与支持范围

- 同机部署使用本地权重；跨机部署通过成功的同步任务绑定目标路径、机器、环境和文件清单。更换绑定后需要重新同步或选择相应的已成功任务，不会仅凭一条可写路径授予部署权限。
- 选择来源训练任务时，源权重路径与该任务已记录产物的关系仅用于警告，不阻止独立登记或外部训练权重的同步与部署。未匹配时仍使用所选训练配置，因此需保证模型结构和归一化参数一致。同机部署通过原生成配置恢复；跨机部署在源机器完成配置恢复后导出推理所需模型与处理合同，目标机器不依赖原训练数据、归一化源路径或初始权重路径。
- 当前支持单组数据合同的 OpenPI 动作策略。价值模型（ReCap `value`）不作为动作策略部署。多数据集任务的推理处理器及归一化选择尚未实现，当前明确阻止部署，避免隐式选用第一组数据或错误统计。
- 此功能需要目标 Agent 支持 `POLICY_DEPLOY_*`，跨机同步还需要源 Agent 支持 `POLICY_EXPORT`、`POLICY_EXPORT_STATUS` 和 `POLICY_EXPORT_CANCEL`。目标 Agent 的新心跳必须声明 `POLICY_DEPLOY_PORTABLE_V1`；缺失时同步和跨机部署会明确阻止，并提示先更新目标 Agent。跨机服务就绪回执还必须同时匹配推理配置与 checkpoint 清单摘要，旧 Agent 忽略新参数时不会被视为成功。
- 部署记录、启动进程身份及测试结果均持久保存。Agent 重启后通过进程身份恢复管理；不会仅凭复用的 PID 停止其他进程。
