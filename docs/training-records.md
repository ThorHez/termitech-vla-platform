# 删除训练任务记录

## 列表显示与历史查询

「训练任务」列表统一展示模型训练和数据同步，按创建时间从新到旧排列，每页固定显示 20 条。使用上一页、下一页查看更早的历史记录，页脚显示当前范围、总条数及页数。

任务类型、状态和名称/机器搜索会先在全部未删除记录中筛选，再分页显示，不受旧列表接口最近 500 条训练或 200 条同步记录的限制。切换筛选条件或搜索时返回第一页；自动刷新保留当前页，删除某页最后一条记录后回到有效页。

页面使用只读接口 `GET /api/v1/background-tasks`，权限为 `platform.read`。接口支持 `page`、`page_size`（默认 20，最多 100）、`type`、`status` 和 `q` 参数，返回当前页任务及筛选后的总条数。分页只改变显示和查询方式，不影响历史记录保留或任务执行。

若页面已更新但旧后端尚未提供分页接口（返回 `404`），页面会兼容读取旧接口并对已加载记录分页，同时明确提示训练最多 500 条、同步最多 200 条的范围。更新管理服务后自动使用全量历史分页；权限、服务或网络错误仍会显示实际错误。

## 训练模型命名

OpenPI 自动发现的模型按「训练任务名 · 短任务 ID / 检查点步数」命名，例如 `pick_elec_meta_train_261101 · 59d25a86 / 59999`。同名训练使用短任务 ID 区分；同一任务的第 2 次及以后执行额外显示「执行 N」。长名称仅裁剪训练名，保留任务 ID 和步数。

模型同步副本继承该名称，默认同步标题再附加「资产同步」。旧版本生成的配方名会按已记录的训练来源或经过校验的同步来源自动更新；手动登记或明确自定义的名称保留。配方名仍保存在模型元信息中，实际模型目录、资产 ID、版本和同步目标目录不变。

名称升级不会改写已有同步快照。旧自动名称和对应新名称可视为同一模型的显示名变化，旧同步仍可重试；路径、版本、元信息、机器目录和 SSH 身份的变化仍会阻止重试。

## 本次训练使用的运行环境

同一台机器的一个 Agent 可以登记多套代码目录与 Python 环境。创建训练时选择“本机运行环境”，任务详情展示本次使用的环境名称、标识、代码目录和 Python 解释器。

环境信息由 Agent 在预检和启动时写入代码快照的 `runtime_profile`，随训练记录和 provenance 保留。详情优先使用最近一次执行记录的快照，尚未启动时使用本次预检快照；环境重新绑定后，历史任务仍显示当时的路径。旧快照中已记录的代码目录继续展示，缺少名称时显示环境标识，未记录的 Python 路径显示“未记录”，不从当前绑定补填。

## 创建者与本次执行

列表和详情显示原任务创建者，共享读取不授予修改权限。取消、删除及管理关联部署或同步记录按创建者核对，管理员可以统一处理；历史无归属记录由管理员处理。操作员可复用共享训练的配置创建自己的新任务，不会改变原任务。

同步重试和推理服务启动另外记录本次执行发起者 `execution_user_id`，管理员接手执行时原 `owner_user_id` 保持不变。GPU 预留和启动权限按本次发起执行的账号检查。禁用账号或撤销训练权限会暂停尚未开始且未首次投递的执行；已经投递的命令和运行中的任务保持原重传、进程和资源状态，需另行明确停止。

## 删除训练记录

在「训练任务」列表或任务详情中点击「删除记录」，核对任务名称后确认。管理员可删除全部已结束记录，操作员仅可删除自己创建的记录；缺少创建者的历史记录仅管理员可删除，只读账号没有此操作。

仅支持删除已成功、失败或取消的任务。排队、启动、运行、取消中或状态未知的任务必须先结束；取消任务后需要等待 Agent 确认执行结束和资源释放。

**有关联部署记录的训练任务不允许删除，必须先删除所有关联部署记录。** 已停止、失败的部署，以及只有权重同步的部署准备记录，同样属于这一限制。校验依据实际的部署、同步和来源训练关联，不根据机器或权重目录推测。

删除后，该任务从训练列表、机器详情中的历史训练、首页统计及告警中移除，任务详情、日志、事件和指标接口不再可访问。已登记的输入资产、模型和 Checkpoint 保持可用；机器上的目录和文件不会因删除记录而被操作。

## 先删除部署记录

在「真机部署」列表或部署详情中点击「删除部署记录」并确认。推理服务必须已停止或失败，且没有未完成操作、进程或服务地址；所有关联权重同步也必须已成功、失败、取消或中断。进行中的服务和同步需要先停止或结束，删除记录不会代替停止操作。

若记录拥有的同步结果仍被其他部署记录引用，需先删除引用它的部署记录，再删除拥有同步结果的记录。删除全部关联部署记录后，才能删除来源训练记录。

`DELETE /api/v1/deployment-records/{record_id}` 使用 `training.write` 权限，并核对创建者或管理员身份，成功和重复删除均返回 `204`。服务或同步未结束时返回 `409 DEPLOYMENT_RECORD_ACTIVE`；同步仍被其他部署引用时返回 `409 DEPLOYMENT_RECORD_IN_USE`。删除后，部署与对应的服务、同步历史从页面及公开接口移除，不能通过旧地址重启或重试；已登记的资产、权重和机器文件保留。

## 接口与数据保留

`DELETE /api/v1/runs/{run_id}` 使用 `training.write` 权限、创建者或管理员身份校验以及现有会话/CSRF 校验。删除成功返回 `204`，重复删除同一记录仍返回 `204`；不存在的任务返回 `404`。任务尚未结束、仍有活动执行或 GPU 分配时返回 `409 RUN_NOT_TERMINAL`；存在尚未删除的关联部署记录时返回 `409 RUN_HAS_DEPLOYMENTS`。

训练和部署记录采用逻辑删除：数据库保留任务、执行记录、日志/指标事件、同步回执及资产来源关联，以支持已登记资产的追溯和 Agent 的延迟重传。此功能不提供恢复入口，也不清理历史数据库存储。已删除的训练不能作为新部署或同步的来源。

预检与提交幂等记录会保留，避免延迟的提交请求再次启动训练。使用原幂等键重放已删除任务的提交返回 `409 RUN_DELETED`；换一个幂等键复用原预检仍返回 `409 PREFLIGHT_ALREADY_USED`。如需再次训练，应重新配置并预检。

旧数据库启动时会自动添加可空的 `runs.deleted_at` 和 `deployment_records.deleted_at` 字段，已有记录默认可见。

## 删除数据同步记录

「训练任务」页同时展示模型训练和数据同步。数据同步记录可在列表行或同步详情中删除，需要 `assets.transfer` 权限，并核对创建者或管理员身份。仅支持已成功、失败、取消或中断的同步；排队、传输、校验或取消中的同步必须先结束。

确认删除后，记录及同步日志不再显示，已登记的源资产、目标资产和归一化绑定保持可用，机器上的源文件、目标文件及未传完的部分文件保留。删除记录不会再次启动同步或执行机器文件清理。

`DELETE /api/v1/asset-transfers/{transfer_id}` 成功及重复删除返回 `204`；未结束时返回 `409 ASSET_TRANSFER_NOT_TERMINAL`，不存在时返回 `404`。逻辑删除标记保存在 `asset_transfers.deleted_at`，旧库启动时自动补齐。删除后详情、重试和取消接口返回 `404`；使用原幂等键重放提交返回 `409 ASSET_TRANSFER_DELETED`，防止重新显示或启动已删除的任务。
