# 配方详情、自定义配方与配置提交

## 常规训练与启动前 config 核对

常规创建流程为「选择数据和初始模型 → 确认训练方式与参数 → 预检启动」。第一步选择机器、运行环境、已登记数据集、各自的归一化参数与初始权重；第二步确认 SFT 或 ReCap 阶段、Pi0/Pi05、全量或 LoRA 微调、模型动作维度、预测长度及训练参数。普通流程无需填写 `config_name`。代码配方、自定义配方及自定义训练入口保留在高级设置中。

自动组装的训练参数直接支持训练步数、全局 batch、数据加载进程数、FSDP 分片设备数、学习率预热/峰值/衰减总步数/最终值、梯度裁剪、EMA、日志间隔、检查点保存间隔与保留周期。初始权重来自第一步的基础模型资产；这些参数不改变已选数据集及处理组合。可选字段清空后继承训练环境或所选配方，FSDP 清空则跟随本次申请的 GPU 数量；EMA 的原生关闭状态会明确显示；LoRA 默认关闭，只有用户明确启用时才填写系数。打开、恢复或切换配置时，缺少的训练参数会直接填入已读取的配方值或推荐默认值，已有有限数值保持不变；这些实际显示值会作为本次参数提交，并按账号存入草稿和训练模板。用户正在编辑、清空输入时不会被持续回填。FSDP 必须整除申请 GPU 数，余弦衰减总步数须大于预热步数，最终学习率不得超过峰值；预检会在继承的实际配置上再次校验。高级配方使用其他学习率计划或优化器时，只能修改该组件实际提供的参数，不会自动切换算法。

GPU 分配支持自动选择和指定设备。自动模式只填写数量；指定模式在当前机器的 GPU 列表中多选，数量跟随所选设备，并以 `requested_gpu_uuids` 冻结到预检请求和训练记录。设备编号仅用于展示，调度与 `CUDA_VISIBLE_DEVICES` 使用稳定 UUID。指定设备忙、已预约或状态未知时保持排队，不会改用其他空闲卡；设备缺失时等待其恢复。切换机器会清除原指定设备，恢复草稿、模板和重训练时会核对原 UUID。训练详情分别显示请求设备与实际分配设备。旧任务继续使用自动分配；GPU 选择不写入模型 Python 配方，而由平台在启动时约束设备可见范围。

自动组装复用所选 `openpi-umi` 中已有的模型配置、`ComposableDataConfig`、独立数据处理器及 `MultiDataConfigFactory`，不为每次训练修改项目配方源码。每组数据必须具有明确的处理器，禁止沿用没有基础配方的 `recipe_index`。多数据集各自绑定归一化统计和混采权重；不兼容的模型、阶段和处理方式由预检报错。

Pi05 自动混采要求每组使用登记的组件组合处理，以验证历史状态展平后的宽度并确定统一填充维度；旧专用处理器混采继续使用高级配方。自动价值训练使用骨干及价值头全量更新，暂不支持 LoRA；仅训练价值头等冻结方案使用高级代码配方。组合视觉从各资产的明确槽位与 RGB/Depth 类型联合确定，同一槽位的类型冲突会报错。

正式训练的预检结果包含 `automatic_preflight.plan.generated_config`，记录 `training_config.py` 的 Python 源码和 SHA-256。代码展示本次冻结请求、实际解析配置及其模型、数据处理、优化器和冻结规则依赖；动态代码对象明确保留训练项目依赖，不把有界配置投影宣称为独立模型实现。输出目录由运行器分配，生成代码通过 `build_config(output_dir)` 绑定，从而保持预检与实际启动的代码摘要一致。

导出代码按实际训练入口保留当前配方的最小构造参数，省略可安全还原的默认值和无关扩展。普通 SFT 不展开组合处理器未使用的 ACP 参数、Shellgame、Value、UOT 或 PyTorch 专项设置；相应训练方式启用时保留有效参数。未知自定义入口和处理器按其显式配置保守保留，不通过字段同名推断用途。代码只保存一份构造视图及重建所需请求，不再重复转储全量默认配置；完整解析结果仍计算为 `RESOLVED_CONFIGURATION_SHA256`，使被省略的有效默认值变化也会改变待确认代码摘要。生成规则更新后需重新预检并确认，已有预检和历史训练的冻结代码不回写。

用户检查生成代码并勾选确认后，启动请求携带 `confirmed_config_sha256`。服务端拒绝缺失或与本次预检不符的确认，确认摘要与时间写入任务；调度命令与运行器再次核对同一摘要，实际启动重新解析并比较完整计划。修改配置或重新预检后，必须重新确认。旧 Agent 未提供代码预览时不能启动正式训练，需要先更新 Agent。smoke 链路测试不要求训练配置确认。

`training_config.py` 随正式训练输出保存，便于复查。生成、核对和预检均不执行训练步骤，也不表示模型效果或 GPU 训练已经验证。

在“新建训练 → 机器与模板”选择机器、环境与代码配方，平台通过该机器 Agent 读取实际 OpenPI 配置。详情按训练、优化器、模型和数据分组，保留 Python 定义、文件位置、Git SHA、源码 SHA-256 与本地修改信息。

## 编辑和另存

支持训练步数、batch size、峰值学习率、EMA 衰减、数据加载进程数、日志间隔、检查点保存间隔、保留周期、随机种子和梯度裁剪的类型及范围约束。未静态展开的这些字段仍可在“其他可覆盖参数”中明确填写。

`data`、`model`、`optimizer` 和 `lr_schedule` 下已经静态读取的算法参数、数据处理选项、布尔值、字符串、空值及有界列表也可以编辑。列表输入使用 JSON，保留原有元素类型；整组列表可编辑时，不重复开放各元素输入。Python 构造器、动态表达式和未读取的任意字段保持只读，不能从网页提交 Python 代码。运行目录、配方身份等由平台管理的字段不能编辑。

数据集路径 `repo_id`、`assets` 及其目录/标识、归一化统计路径、初始模型加载器及路径、混采权重等由训练资产绑定管理，在分组和“全部字段”中均只读，并标为“由训练资产绑定”。代码默认值折叠展示，仅供参考；本次训练须在“资产与参数”明确选择已登记的数据集、归一化参数与初始模型，并设置混采权重。`base_config.prompt_from_task`、`use_quantile_norm`、`action_sequence_keys`、state padding 等数据处理参数仍可编辑。

旧版本或未完成草稿含有资产覆盖时，界面列出冲突字段，阻止直接保存和用于新训练。用户可核对移除项、保留旧草稿后保存新的干净版本；不会原地改写历史修订或已冻结的训练。已发出的写入任务先查询结果，已有 Git commit 回执会保留，不能把它当作未提交草稿清除或重写。

修改后点击“另存为新配方”或“保存新版本”，填写平台显示名称、独立的代码配方名称 `config_name` 和说明，并核对差异。`config_name` 只接受 1–255 个英文字母、数字、下划线或连字符，必须使用新的代码名称。点击“保存并写入 config”会先保存平台草稿，再请求该机器的 Agent 将配置作为独立配方写入其来源文件，并自动执行一次 Git commit。拆分项目使用 `training/recipes/sft.py`、`recap.py`、`mem.py`、`rlt.py` 或 `uot.py`；旧项目仍写 `config.py`。它保留原代码配方，不自动推送仓库。

只有配置写入和提交成功后，界面才选中新的可训练版本，同时显示新 `config_name` 和提交 SHA。成功结果会在同一平台配方中生成新的不可变修订：基础配方改为新代码名称、来源指向提交后的 SHA、覆盖项清空。平台修订号因此不等于代码配方名称后缀，也不能用保存草稿成功冒充源码提交成功。

写入要求来源版本仍与读取时一致、目标配方文件没有未提交修改且 Git 仓库可以提交，且代码目录中没有进行中的训练或另一次写入。冲突会明确提示先等待训练完成或使用独立代码副本，不会在正在训练的代码目录中回写。提交只包含来源文件中新配方的变更；仓库其他已有的修改及暂存内容会保留，并从这次提交中排除。保存不会启动训练。

平台草稿保存后，即使写入失败或页面离开，仍保留草稿与写入任务 ID；重新进入可继续查询同一任务，网络错误不会再次创建草稿。失败任务保留终态回执，不能把重复请求当作重新执行。如果源码已提交但提交后详情读取失败，失败结果仍显示实际提交 SHA 和目标代码名称；应在代码配方中选择该名称重新读取，不能误报为未提交或重复写入。处理源码冲突等问题后，可以保留草稿并重新读取配置，再保存新版本。浏览器会在当前标签页的 sessionStorage 中保留待查询任务，直到成功选中或显式重新读取。

配方记录按机器及训练环境隔离。每个修订保存基础代码配置名称、完整来源快照、修改项和内容摘要；已保存修订不可原地修改。模型和数据不复制。当前代码与保存时不一致时显示旧快照，需显式选择以当前代码重新读取并保存新修订。

## 本次训练

平台配方名称可以是中文，与 OpenPI 的 `config_name` 分开。每组数据可以在资产与参数步骤独立选择所选训练环境提供的数据处理器，并编辑其静态处理参数；也可保留“沿用配方数据项”的旧方式。处理器目录包含其他已实现的类，选择范围不限于当前配方。处理器兼容性由本次预检核对，不通过名称相似自动推荐。训练调用基础 `get_config(base_recipe)` 后应用受支持的静态值覆盖，再应用本次参数及资产/GPU/输出目录绑定。完成回写的修订直接使用新代码配方名，其覆盖项为空。

步数、batch 和学习率从当前配方的静态值与保存覆盖项带入；下一步可以仅为本次训练修改。源码中的未解析默认值不能冒充实际值，未解析的必要参数需明确填写。

训练请求只接收中台保存的修订 ID，不接受浏览器上传可执行定义。预检、提交、排队、Agent 启动及实际 STARTED 事件都核对冻结修订。源码 Git SHA、tracked staged/unstaged 摘要与配置文件摘要发生变化时，拒绝继续使用旧修订。完整训练代码及未跟踪文件仍由既有预检/启动代码快照记录；详情来源指纹不宣称覆盖 ignored 文件或完整依赖环境。

新修订显示“预检时验证”。Agent 在每次训练预检时解析冻结的修订、应用覆盖与本次资产绑定，自动检查配置和本机资产；无需管理员修改 `metadata.validated_recipe_revisions`。每次预检绑定确切 `definition.digest`，不能借用基础配方或上一修订的结果。旧验收字段仅作为历史记录展示。

自动证据保存在 `code_snapshot.automatic_preflight`，包含 `schema_version: 1`、`scope: configuration_and_local_assets`、解析后的入口与全部数据集计划及 `plan_digest`。提交时验证证据，实际启动前重新检查并比较；代码、配置或关键本机资产变化后必须重新预检。预检只验证配置与资产，不执行训练，不表示 loss、checkpoint 或模型效果已经通过验收。

训练输出保留原 `resolved_training.json` 请求 spec，同时新增 `effective_training.json`：记录覆盖和平台绑定后的有界 dataclass 配置投影。函数、复杂对象及超限部分明确标记未解析；此快照位于数据工厂执行之前，不等同完整动态数据管线的展开结果。

## 当前限制

- 不支持从网页执行或修改任意 Python、构造器及模型/数据处理逻辑；这些变更通过新的训练代码版本提供。
- 多数据集配方使用 `scripts/train_multi_dataset.py`。训练向导的数据绑定会按用户确认的列表重建选中的数据子项、归一化绑定及混采权重；state padding 和数据处理语义保留，最终数据计划全部参与预检。平台配置回写与本次训练资产绑定是两个步骤，保存配方不等于已经验证数据或启动训练。
- 配方详情支持主配置文件以及由其显式注册的上述五个配方文件中的唯一静态配方；动态生成、有歧义、未接入主注册表或其他任意模块中的定义会提示限制。读取保持有界，不执行训练代码。
- 当前使用既有单项目管理员模式，不新增多用户权限系统。

## 接口

- POST `/api/v1/nodes/{id}/recipe-details`：`{profile_id,recipe}`；GET 同路径 `/{query_id}` 轮询 PENDING/READY/FAILED，15 秒执行超时。
- GET `/api/v1/recipes?node_id=&profile_id=`：返回自定义配方及最新修订。
- POST `/api/v1/recipes`：`{node_id,profile_id,name,description,detail_query_id,overrides}`；来源只能取自近期成功的 Agent 详情查询。
- GET `/api/v1/recipes/{id}`；POST `/api/v1/recipes/{id}/revisions`：`{detail_query_id,overrides,description?}`。
- GET `/api/v1/recipe-revisions/{id}`：读取不可变历史修订及原始详情。
- POST `/api/v1/recipe-revisions/{id}/writeback`：`{config_name}`；返回写入任务；GET `/api/v1/recipe-writebacks/{id}` 轮询 `PENDING/SUCCEEDED/FAILED`，成功结果包含 `commit_sha` 和更新后的 `recipe`。同一修订和目标代码名称重复请求返回同一个任务。
- POST `/api/v1/run-previews` 可带 `recipe_revision_id`；服务端解析定义，冻结到预检请求和代码快照。旧的代码配方请求继续兼容。

新增数据库表通过现有初始化创建，不重写旧 Run 或 Profile。详情和配方接口均使用管理员鉴权和 no-store 响应。

组合处理的自动预检还会使用所绑定的 OpenPI Python，在独立 CPU 进程中通过真实 LeRobot 加载器读取首、中、末样本，执行与训练一致的 repack 和 data transforms。`dataset_samples` 失败或缺少正样本证据时不能提交训练；旧 OpenPI 项目须提供 `ComposableDataConfig.processing_sample_config` 接口。样本检查不下载模型、不执行训练，也不代表所有视频帧均可解码。

新建自动训练会按申请 GPU 数推荐 FSDP 分片数，以及每 GPU 2 个、最多 16 个的数据加载进程；Agent 已上报可见 CPU 数时，加载进程推荐不超过该数减一，单 CPU 可推荐 0。CPU 数未知时只使用 GPU 启发式。CPU 数量来自进程 affinity 或逻辑 CPU 数，不表示空闲 CPU 或独占配额。推荐是起始值，手动修改或清空后停止自动覆盖；使用推荐值按钮可恢复跟随。旧草稿、模板中明确填写的参数保持不变，推荐模式也会随草稿和模板保存。
